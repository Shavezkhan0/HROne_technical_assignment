# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Returns hardcoded `{"status": "ok"}` without checking MongoDB connectivity. | Stop MongoDB or pass an invalid URI, then call `GET /health`. It returns HTTP 200 `{"status": "ok"}` instead of reporting service unreachability. | Wrapped `db.command("ping")` in a `try...except` block, raising `HTTPException(503, "Database unreachable")` if the database is down. |
| 2 | `compute_late_minutes` (lines 33–37) | Uses naive local datetimes instead of IST, and truncates `(punch_in - start).total_seconds() / 60` with `int()` before comparing `minutes > 10`. Because `int(seconds / 60)` throws away the seconds, 10 minutes 30 seconds becomes 10, and 10 > 10 is false, so someone 10 minutes and 30 seconds late is not marked late. | On a 09:30 shift, punch in at 09:40:30 IST. `compute_late_minutes` calculates `int(630 / 60) = 10` and returns `0` instead of `10` (any arrival strictly after 10:00 should incur late minutes). | Replaced with `late_minutes()` calculating `delta_seconds = (punch_in_ist - shift_start_ist).total_seconds()` on IST-aware datetimes; if `delta_seconds > 600`, returns `math.floor(delta_seconds / 60)`. |
| 3 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round()` on floats, which performs round-half-to-even ("banker's rounding") rather than round-half-up. | Work from 09:30:00 to 17:37:30 (exactly 8.125 hours). `compute_work_hours` returns `8.12` because `2` is even, whereas round-half-up requires `8.13`. | Replaced with `work_hours()` and `half_up()` using `Decimal(str(secs / 3600.0)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44–47) | Lacks the 30-minute minimum threshold; subtracts naive `punch_out` from IST-aware `end`, raising `TypeError`; and builds `end` on `date_str` (the attendance date) without adding a day for overnight shifts. | Calling `compute_overtime` with a naive `punch_out` crashes with `TypeError: can't subtract offset-naive and offset-aware datetimes`. On a punch-out 15 minutes past shift end, it returns `15` instead of `0`. For a 22:00–06:00 overnight shift starting on 6 July, `end` is built as 06:00 on 6 July, so a punch-out at 06:40 on 7 July gives about 1,480 overtime minutes (24h 40m) instead of 40. | Replaced with `shift_bounds_for_date()` adding 1 day to `end_dt` when `shift_end <= shift_start`, converted datetimes to IST, and enforced `mins if mins >= 30 else 0` in `overtime_minutes()`. |
| 5 | `EmployeeIn` (lines 53–60) | Lacks field format constraints, length limits, and calendar date validation. | `POST /employees` with `{"emp_code": "bad", "name": "   ", "email": "foo", "department": "", "joined_on": "3989-87-38", "shift_start": "09:00", "shift_end": "09:00"}` returns 201 Created instead of 422 Unprocessable Entity. | Added Pydantic `Field` regex constraints for `emp_code` (`^EMP\d{4,6}$`), `email`, and shift times; validators stripping whitespace on `name`/`department`; `date.fromisoformat()` validation on `joined_on`; and model validator ensuring `shift_start != shift_end`. |
| 6 | `create_employee` (lines 78–85) | Check-then-insert race condition with no unique index on `emp_code`; uses naive `datetime.now()`; and returns `created_at` as a Python datetime (serialized to ISO string) instead of epoch milliseconds. | Concurrent POST requests with the same `emp_code` can both pass `find_one` and insert duplicates or crash; response JSON returns `created_at` as an ISO string (`"2026-10-13T10:00:00"`) instead of integer milliseconds (`1791884278776`). | Created a unique index on `emp_code`, caught `DuplicateKeyError` to return HTTP 409 Conflict, used `datetime.now(timezone.utc)`, and serialized `created_at` with `to_epoch_ms()`. |
| 7 | `list_employees` (lines 88–96) | Off-by-one pagination (`skip = page * page_size`); `total` counts `{}` unconditionally, ignoring the department filter; results are unsorted; and query parameters lack bounds. | `GET /employees?page=1&page_size=20` sets `skip=20`, skipping the first 20 employees and returning page 2. `GET /employees?department=HR` returns the total count of all employees in the company instead of the HR department count. | Calculated `skip = (page - 1) * page_size`, updated total to `db.employees.count_documents(q)`, added `.sort("emp_code", 1)`, added `Query` constraints (`page >= 1`, `1 <= page_size <= 100`), and formatted `created_at` to epoch milliseconds. |
| 8 | `punch_in` (lines 100–121) | Crashes with HTTP 500 (`TypeError`) if employee is missing; `datetime.fromtimestamp(...)` and `datetime.now()` use the server's local time, not IST, so on a UTC server a 04:00 IST punch-in gets the previous day's date (even for normal day shifts), while overnight shifts are not handled; check-then-insert race condition; does not truncate sub-seconds; returns string `id` and datetime objects; and leaves `status` unvalidated. | `POST /attendance/punch-in` for an unknown `emp_code` raises 500 `TypeError: 'NoneType' object is not subscriptable` instead of 404. On a UTC server, a punch-in at 04:00 IST (22:30 UTC previous day) gets the previous day's date even on day shifts, and overnight shifts at 05:00 IST record today's date instead of yesterday's. Response contains `"id": "..."` and ISO timestamps instead of epoch milliseconds. | Added employee check raising 404; converted UTC timestamp to IST using `ist_date_for_punch_in()`; truncated to whole seconds via `floor_to_second()`; created unique index `(emp_code, date)` and caught `DuplicateKeyError` returning 409; validated status with `PresenceStatus` enum; stripped `_id`/`id`; and serialized timestamps with `to_epoch_ms()`. |
| 9 | `list_attendance` (lines 124–150) | Loads the entire collection into memory with `find(q)` and sorts/slices in Python; lacks tie-breaker sort; returns string `id` and raw datetime objects; omits default fields (`half_day`, `history`) for legacy records; and lacks validation for dates, status, or pagination bounds. | Server memory spikes on large collections; `GET /attendance?date_from=2026-99-99` returns 200 instead of 422; records include `"id"` and ISO date strings; legacy documents omit required fields like `half_day: false` and `history: []`. | Validated date filters with regex and `date.fromisoformat()`; validated `date_from <= date_to`; pushed `.sort([("date", -1), ("emp_code", 1)])`, `.skip()`, `.limit()`, and `count_documents(q)` to MongoDB; removed `_id` and `id`; backfilled default schema fields; and converted timestamps to epoch milliseconds. |

Also note anything you looked at and decided was **not** a defect, and why.

- **`IST` timezone constant (line 25):** Looked at `IST = timezone(timedelta(hours=5, minutes=30))`. This correctly defines Indian Standard Time as UTC+05:30.
- **`doc.pop("_id", None)` (lines 84, 120):** Looked at popping `_id` after `insert_one`. This correctly prevents leaking MongoDB's internal BSON ObjectId in JSON responses.
- **Default shifts in `EmployeeIn` (lines 58–59):** Looked at `shift_start: str = "09:30"` and `shift_end: str = "18:30"`. These defaults accurately represent the standard working shift defined across the dataset.
